# Orders — Task 1 + Task 2, C++17

Продолжение решения задания 1. Заказ сохраняется как `pending`; четыре фоновых работника выполняют резервирование, оплату и компенсацию при отказе банка. Повторы оплаты используют постоянный ключ `pay:<order_id>`.

## Задание 2

- Статус `paid` и запись в `outbox` сохраняются одной транзакцией.
- Два отдельных отправителя публикуют `order.paid`. При ошибке или таймауте событие повторяется с прежними `id` и временем. После `202` сохраняется `sent = true`.
- `POST /webhooks/delivery` сохраняет уникальный id события в `inbox` и начисляет бонусы в одной транзакции. Дубликат получает `200` без повторного начисления.
- `GET /users/{id}/bonus` возвращает баланс, для неизвестного покупателя — ноль.

## Файлы

- `src/main.cpp` — настройки, запуск и пять HTTP-маршрутов.
- `src/service.hpp`, `src/service.cpp` — интерфейс и этапы оформления заказа.
- `src/events.cpp` — отправка событий, обработка доставки, чтение бонусов.
- `src/database.hpp`, `src/database.cpp` — PostgreSQL, SQL с параметрами и создание таблиц.
- `src/core.hpp` — проверка входных данных, расчёты и circuit breaker.
- `tests/core_tests.cpp` — тесты расчётов, входных событий и circuit breaker.
- `vendor/` — cpp-httplib и nlohmann/json с лицензиями.
- `CMakeLists.txt`, `Dockerfile` — сборка, CTest и запуск контейнера.

## Запуск в стенде

Из корня репозитория: `make scenarios TASK=1`, затем `make scenarios TASK=2`.
В Docker CTest выполняется автоматически при сборке.

Для отдельной сборки нужны C++17, CMake и libpq:

```sh
cmake -S orders -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Переменные окружения: `DATABASE_URL`, `PAYMENT_URL`, `INVENTORY_URL`, `EVENTS_URL`; `PORT` по умолчанию 8080.

## Ограничения

Сетевые запросы ограничены таймаутами, но во время одного шага работник держит транзакцию и блокировку строки. Это упрощает координацию, но занимает подключение к базе. Circuit breaker хранится в памяти. Outbox и inbox не очищаются; при очистке нужно учитывать поздние повторы и создание событий старым paid-заказам при запуске. Повторы отправки допускаются; у копий одного события один id.
