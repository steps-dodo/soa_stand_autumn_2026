# Orders — задание 1, C++17

Сервис сохраняет заказ в PostgreSQL и возвращает `201` со статусом `pending`.
Четыре фоновых работника резервируют товар, проводят оплату и обновляют статус.
Повтор оплаты использует постоянный `Idempotency-Key`: `pay:<order_id>`.
При отказе банка `402` сначала снимается резерв, затем заказ становится `rejected`.

Временные ошибки приводят к повтору с увеличением задержки и случайным разбросом.
Общий circuit breaker ограничивает обращения к недоступному банку.
Работники выбирают разные заказы через `FOR UPDATE SKIP LOCKED`.

## Файлы

- `src/main.cpp` — запуск, настройки и HTTP-маршруты.
- `src/database.hpp`, `src/database.cpp` — подключение к PostgreSQL, SQL-запросы и создание таблицы.
- `src/core.hpp` — проверка заказа, расчёт суммы, задержки и circuit breaker.
- `src/service.hpp`, `src/service.cpp` — создание заказов и фоновая обработка этапов.
- `tests/core_tests.cpp` — проверки расчётов и circuit breaker.
- `CMakeLists.txt`, `Dockerfile` — сборка, тестирование и запуск контейнера.
- `vendor/` — cpp-httplib и nlohmann/json с их лицензиями.

## Запуск

Из корня стенда: `make up`, затем `make scenarios TASK=1`.
Остановка: `make down`.

При сборке контейнера автоматически выполняется CTest.
Для отдельной сборки нужны C++17, CMake и библиотека PostgreSQL libpq:

```sh
cmake -S orders -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Настройки сервиса передаются через `DATABASE_URL`, `PAYMENT_URL`, `INVENTORY_URL` и `PORT`.
Эндпоинты: `GET /healthz`, `POST /orders`, `GET /orders/{id}`.

## Ограничения

Реализовано только задание 1. События и бонусы из задания 2 не реализованы.
Состояние circuit breaker хранится в памяти и сбрасывается при перезапуске.
На время одного шага заказа транзакция и блокировка строки остаются открытыми,
в том числе во время ограниченного таймаутом сетевого запроса.
Это упрощает координацию четырёх работников, но занимает подключение к базе.
